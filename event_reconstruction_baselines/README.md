# E2VID and ET-Net comparison container

This directory is a self-contained, single-GPU runtime for running the
official E2VID and ET-Net implementations on the RGBE-Gaze validation export.
It does not modify the original eBIRD Dockerfile or execute either model at
image-build time.

The vendored source revisions are recorded in
`THIRD_PARTY_VERSIONS.txt`. The two repositories are included without their
nested Git metadata so that this directory can be committed as ordinary source
files in the eBIRD repository.

## Expected data

Copy the validation export generated by the dataset repository to the local
computer. The default host path expected by `run_docker.sh` is:

```text
/home/ignacio/Projects/UOH/Event-Cameras/dataset/event-based_datasets/reconstruction/rgbe-gaze-validation_exp5/
```

The export must contain at least:

```text
generated/
├── manifest.csv
├── targets_512/
├── e2vid_firenet_512/user_*/exp5/events.txt
└── etnet_256/user_*/exp5/events.h5
```

These are continuous per-sequence streams. Do not split them into one file per
RGB frame: both methods keep temporal state while processing a sequence.

## Pretrained weights

Weights are intentionally not committed. Place them in a host directory and
mount that directory as `/app/weights`:

- E2VID lightweight checkpoint: `E2VID_lightweight.pth.tar`, from the official
  E2VID release URL in `third_party/e2vid/README.md`.
- ET-Net checkpoint: `etnet_checkpoint.pth`, downloaded from the official
  Google Drive link in `third_party/et-net/README.md`.

Example:

```bash
mkdir -p weights
wget "http://rpg.ifi.uzh.ch/data/E2VID/models/E2VID_lightweight.pth.tar" \
  -O weights/E2VID_lightweight.pth.tar
# Download the ET-Net checkpoint manually and save it as weights/etnet_checkpoint.pth.
```

## Build the image

From this directory:

```bash
./build_docker.sh
```

The Dockerfile uses the PyTorch 1.13.1 CUDA 11.6 runtime and pins older NumPy
and scikit-image versions required by the original code (`np.int` and
`compare_ssim`). No model is run during the build.

## Start an interactive container

The default host GPU is GPU 0. Select another GPU without changing the image:

```bash
GPU_ID=0 ./run_docker.sh
```

Override host data, weights or output locations when necessary:

```bash
GPU_ID=0 \
RGBE_VALIDATION_DIR=/path/to/rgbe-gaze-validation_exp5 \
BASELINE_WEIGHTS_DIR=/path/to/weights \
BASELINE_OUTPUT_DIR=/path/to/outputs \
./run_docker.sh
```

The command opens Bash inside the container. The mounts are:

| Container path | Purpose |
| --- | --- |
| `/app/data` | Read-only RGBE-Gaze validation export |
| `/app/weights` | Read-only pretrained checkpoints |
| `/app/outputs` | Writable reconstruction outputs and logs |
| `/app/event_reconstruction_baselines` | Read-only scripts and vendored source |

## Run E2VID

Inside the container:

```bash
bash scripts/run_e2vid.sh
```

The wrapper processes every `events.txt` sequence with the recurrent E2VID
model and 33.33 ms fixed-duration windows. Outputs and one `inference.log` per
sequence are written under `/app/outputs/e2vid/`.

To select a different visible GPU inside the container:

```bash
GPU_ID=0 bash scripts/run_e2vid.sh
```

## Run ET-Net

Inside the same container:

```bash
bash scripts/run_etnet.sh
```

The wrapper processes every `events.h5` sequence with ET-Net's HDF5 loader and
`between_frames` voxel scheduling. Outputs and one `inference.log` per
sequence are written under `/app/outputs/etnet/`.

To execute both baselines sequentially and keep global logs:

```bash
bash scripts/run_both.sh
```

The combined logs are `/app/outputs/logs/e2vid.log` and
`/app/outputs/logs/etnet.log`.

The wrappers only run inference; they do not train or download weights. They
stop if the expected checkpoint or input directory is missing.

## Logs and outputs

Each sequence has its own log:

```text
/app/outputs/e2vid/user_51/exp5/inference.log
/app/outputs/etnet/user_51/exp5/inference.log
```

The generated images are named according to each original repository's native
inference script. Use `manifest.csv` to associate a sequence/frame index with
the RGBE-Gaze target. The final MSE/SSIM/PSNR comparison should be performed by
a separate alignment script, because native E2VID fixed-duration output
timestamps and ET-Net frame timestamps must be matched to the RGBE-Gaze rows.

## Important reproducibility notes

1. Use the same `exp5`, users and face-ROI export used for the eBIRD comparison.
2. Keep sequence boundaries and recurrent state resets unchanged.
3. Do not compare ET-Net's native 256x256 output directly with 512x512 eBIRD
   targets; resize its output to 512x512 during metric evaluation.
4. Do not commit `weights/`, `outputs/` or generated logs.
